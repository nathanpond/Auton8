# Auton8 0.1 — public release and rename

## Context

The repo goes public to unlock the wiki, CodeQL, secret scanning and private vulnerability reporting, which this plan is free on public repos. Two things must be true first: nothing gets published that shouldn't be, and a stranger arriving at the page finds a product rather than one developer's runbook. At the same time the product is renamed **AutoNate → Auton8** in public-facing surfaces only; internals keep `AutoNate`.

Three audits ran against the tree and full git history. Findings below were verified independently before being written down.

**Decisions taken:** brand is `Auton8`; licence is Apache-2.0; git history gets rewritten; internal docs (`Concerns.md`, `.n8/memory/`, `docs/plans/`) publish as-is.

### The one that decides the schedule

`src/AutoNate.Web/ColorAdmin/` — a **paid ThemeForest theme** — is in history. Commit `911bb7a8` added 43,134 files; **332 MB across 21,921 blobs** are still reachable. It was untracked in `9b9d2787` and is absent from HEAD, so a `.gitignore` cannot help. Publishing republishes a commercial product under a licence that forbids redistribution.

Favourable conditions: **0 forks, 0 stars, 2 open PRs** (both blocked Dependabot bumps). A rewrite costs almost nothing today and becomes impossible to undo the moment the repo is public.

### The one that decides what ships

`infra/postgres/init/02-create-autonate-app-schema.sql:~450` seeds user `admin` with its `password_hash` **and** `password_salt` committed; plaintext is `admin`. It is ungated by environment, and production `appsettings.json:41` sets `AssignSuperAdminToAllExistingUsers: true`, so that account becomes SuperAdmin on first boot.

Its twin: on a clean production database there is **no way to log in at all** — no registration, no setup flow, no `create-admin`, and `POST /api/users` requires auth. One change fixes both.

## Phase 2 — the rename (one PR, after Phase 1)

Public surfaces only. Roughly 70 strings; ~5,600 internal matches stay put.

**Tier 1 — brand chrome (the whole visible rebrand).** Four seed/default copies must move together or an install shows two different names:
- `src/AutoNate.Web/Persistence/DatabaseSchemaInitializer.cs:899` (`'Auto Nate'` ×2)
- `src/AutoNate.Web/Endpoints/SiteAppearanceEndpoints.cs:145,149`
- `infra/postgres/init/02-create-autonate-app-schema.sql:646`
- `src/AutoNate.Spa/src/lib/siteAppearance.ts:15,19` — the only one that affects existing installs
- plus `src/AutoNate.Spa/index.html:8` `<title>` and the admin placeholders at `SiteAppearance.tsx:86,87`

**Data migration, or nothing changes on your own deployment.** All but the SPA default are one-time seeds guarded by `IF NOT EXISTS`. Add a guarded `UPDATE site_appearance_settings SET site_name='Auton8', logo_text='Auton8' WHERE site_name='Auto Nate'` — guarded on the old value so an admin's own branding is never overwritten. This is exactly the drift that left the accent colour fixed in the SPA and stale in the seed.

**Tier 2 — assistant identity.** `SystemPromptBuilder.cs:13,50` (it currently introduces itself as AutoNate), `WebFetchSkill.cs:76`, `AgentChatTrigger.tsx:23`, `AgentSidebar.tsx:424`.

**Tier 3 — prose sweep.** ~27 strings across 14 SPA components: biggest clusters `WorkflowStudio.tsx` (8) and `WorkflowExecutions.tsx` (4). Then backend UI text: ~15 `EventCatalog.cs` category descriptions, `SystemHealthService.cs:88`, `WorkflowBpmnXml.cs:467,489`, `DatabaseSchemaInitializer.cs:1378`.

**Tier 4 — docs.** README, `CLAUDE.md`, `docs/codebase/*` headings, the three sidecar READMEs.

**Do not touch — renaming these destroys data:**

| Identifier | Consequence |
|---|---|
| DataProtection purposes `AutoNate.ExternalConnections.v1`, `AutoNate.Plugins.RolePassword.v1` | every stored provider secret becomes undecryptable |
| `.docx` markers `AUTONATE_BINDING`, `AUTONATE_TABLE_BINDING` | orphans every existing bound document |
| BPMN `http://autonate.dev/workflows`, `${autonateBehaviorDelegate}` | breaks stored workflows and Flowable's own tables |
| Postgres schema `autonate_datastores`, db `AutoNate`, role `autonate_datastore_writer` | data migration across every datastore |
| event `sourceAppId` `autonate.web` | splits the audit history |
| plugin ABI `IAutoNatePlugin`, `AutoNate.Plugin.Abstractions` | breaks third-party plugins |
| 30 `AUTONATE_*` env vars, localStorage keys, `X-AutoNate-*` headers | breaks deployments, resets user prefs, desyncs the Node sidecar |

Also leave: C# namespaces (2,651 lines), `AutoNateDbContext` (544 refs), assembly/solution names. Internal identity staying `AutoNate` is the decision, not an oversight — worth one line in `CONTRIBUTING.md` so it doesn't read as sloppiness.

## Phase 3 — history rewrite (irreversible)

Only after Phases 1–2 are merged and master is green.

1. `brew install git-filter-repo` (not currently installed).
2. Fresh clone to a scratch path; run the rewrite there, never on the working repo.
3. Strip in one pass. **The path list is wider than `ColorAdmin/` — verified after the plan was first written, and stripping only that directory would leave paid content in history:**
   - `src/AutoNate.Web/ColorAdmin/` — 21,921 blobs
   - `src/AutoNate.Spa/src/scss/` — **402 objects**, the ColorAdmin SCSS themes (`scss/default/_app.scss`, plus apple/facebook/google/material/transparent)
   - `src/AutoNate.Web/wwwroot/` — 105 objects of built SPA output (`index-*.js`, `.css`, `.map`); untracked at HEAD, so safe to strip
   - `.playwright-mcp/` (171), `.idea/` (98), `tmpflowable/` (7)
   - root-level `*.png` dev screenshots, via `--path-regex '^[^/]+\.(png|jpg|jpeg|gif)$'` so `public/favicon.png` and `plugins/Auditor/PageTemplates/AuditLog.png` survive
   Re-confirm each path has **zero tracked files at HEAD** immediately before running.
4. Verify before pushing: no `coloradmin` hit in `git rev-list --objects --all`; `size-pack` drops from ~132 MB to roughly 13–15 MB; and — the check that matters most — **`git diff --stat <old-master-sha> HEAD` is empty**, proving the rewrite changed history without changing content. A non-empty diff means the path list caught something live. Then build and run both suites from the rewritten clone.
5. Force-push all branches and tags. Delete `pre-rewrite-backup` once satisfied.
6. Re-clone locally. Do not merge an old clone into the new history.

Known casualties, all acceptable: commit SHAs cited in `.n8/decisions.md` (`01f0f174`) and in issue comments become dangling; the two Dependabot PRs were closed in Phase 0.

## Phase 4 — flip to public

1. **You rename the GitHub repo** to `Auton8` when I say the tree is ready. Then update `.n8/config.yml:repo` and the git remote; GitHub redirects the old URL.
2. `.n8/config.yml`: `visibility: public`, `wiki: enabled`, and change **`security_findings: issues` → advisories**. Its own comment says the rationale is "private repo → issues are already maintainer-only", which expires on the flip; leaving it means the next `/n8-audit` files a world-readable vulnerability list.
3. Flip to public. Then enable, per `.n8/decisions.md`'s own deferred list: CodeQL default setup, secret scanning + push protection, private vulnerability reporting, and a branch ruleset on master requiring a PR.
4. Settings → Actions → **"Require approval for all outside collaborators"**. `ci.yml` is safe by construction — `permissions: contents: read`, no `secrets.*`, `pull_request` not `pull_request_target`, GitHub-hosted runners — but any stranger's PR otherwise triggers a 75-minute backend job.
5. Seed the wiki (it needs one page created in the UI before `.wiki.git` exists).
6. Tag `v0.1.0` and write the release notes.

## Notes on decisions taken

- **Internal docs publish as-is**, per your call. One cheap refinement worth considering separately: `docs/codebase/Concerns.md` asserts "`.github/workflows/` does not exist" and describes fixed issues as open — publishing something *inaccurate* differs from publishing something candid. A regeneration, or a one-line "generated at commit X, since superseded" banner, costs little.
- **`login-bg-17.jpg`** (`src/AutoNate.Spa/public/assets/img/login-bg/`, blob `0f6cdd40`) is tracked at HEAD and shares its filename with a ColorAdmin demo asset. A history rewrite does **not** remove it. I could not confirm byte-identity — the only matching object in ColorAdmin's history is `login-bg-17-thumb.jpg` at a different hash — so the claim is "same provenance, unverified as identical". Since it is the seeded default login cover in two of the four `SiteAppearance` copies, the safe move is to delete it and unify all four on `space.jpg`. Note the backend copies use a `/spa/` path prefix the SPA copy does not, so they already disagree.

- **26 closed `security` issues become world-readable at the flip** (verified: `gh issue list --state closed --label security` → 26). Publishing fixed findings reads as diligence; publishing one closed as wontfix or deferred is a live disclosure. Triage them before Phase 4 — this is a pre-flip gate, and `.n8/config.yml:security_findings` only governs *future* findings.
- **bpmn-js** requires its "Powered by bpmn.io" attribution be preserved; public visibility makes that checkable. Worth confirming the SPA doesn't strip it.
