# Section 508 / WCAG 2.0 AA audit checklist (AutoNate-specific)

Harvested from `.claude/skills/audit-508` on 2026-08-30; corrected after the 2026-11-16 audit. Scope: `src/AutoNate.Spa/src/`, plugin SPA under `plugins/<name>/spa/`, shared chrome. Mantine v9 supplies the baseline (focus trap, Escape, ARIA on Modal/Menu/Combobox); the audit hunts where AutoNate code *escapes* it. Baseline target: WCAG 2.0 AA (508 floor); call out cheap 2.1/2.2 wins.

**A. Text alternatives (1.1.1)** — `<img alt>` (decorative `alt=""`); FA glyphs `<i className="fa fa-…">` need an accessible name on the parent `Button`/`ActionIcon` (`aria-label`, visible text, `title`); standalone `<i onClick>` is always wrong; known FA users `SiteBrand.tsx`, `IconPicker.tsx`. Detect: `grep -rn '<i className="fa' src/AutoNate.Spa/src/` then inspect the parent.
**B. Contrast / color-only (1.4.1, 1.4.3, 1.4.11)** — 4.5:1 text, 3:1 large text + focus rings. `SiteAppearance` is admin-configurable: `applySiteAppearanceToDocument` in `src/AutoNate.Spa/src/lib/siteAppearance.ts` writes `--mantine-*`/`--app-*`; check the configurator validates contrast, that scheme inference from `surfaceBg` luminance doesn't flip wrongly near mid-luminance, that header/sidebar fg/bg pairings have a floor. Status pills / `.row-archived` / `.notification-unread` in `widgets.css` must not be color-only. Compute ratios; cite them.
**C. Keyboard (2.1.1, 2.1.2, 2.4.3, 2.4.7)** — Tab reachability, no traps outside modals, no `outline: none` without replacement, only `tabIndex` 0/-1, skip-to-content in `AppShell.tsx`, custom widgets in `src/AutoNate.Spa/src/widgets/` handle Enter/Space/arrows/Escape, `AgentSidebar` (position: fixed) opens/closes/focuses/returns focus by keyboard. Detect: `grep -rn onClick src/AutoNate.Spa/src/ | grep -E '<(div|span|li|td) '`.
**D. Focus management (2.4.3, 2.4.11)** — non-Mantine dialogs are findings. A dialog mounted conditionally with `opened` hard-coded never returns focus (Mantine's `useFocusReturn` skips the first render): `components/ConfirmModal.tsx` has this bug (#837), `pages/notes/NotesModal.tsx` carries the workaround and is the model. Route change moves focus to `#content` via `hooks/useRouteFocus.ts` — check it does not fire on replace navigations within a page (#838). Mantine's `CloseButton` has no default name; check the theme supplies one (#835). Toasts never steal focus.
**E. Forms (1.3.1, 3.3.x, 4.1.2)** — Mantine `label` prop wires `htmlFor`; errors via the `error` prop (wires `aria-describedby`/`aria-invalid`), not a stray `<Text c="red">`; `required`/`aria-required`; fieldset/legend for groups; login form is highest priority (pre-auth, most trafficked).
**F. Structure / landmarks (1.3.1, 2.4.x)** — one `<h1>`, no skipped levels, per-route `<title>` (`hooks/useRouteDocumentTitle.ts` sets "Page · site name" inside the shell; check routes outside it — login, document editor), `<html lang>`, banner/nav/main/aside landmarks from `AppShell`, real lists.
**G. Live regions (4.1.3)** — Mantine `notifications` uses role=status; spinners paired with `<VisuallyHidden>Loading…</VisuallyHidden>` or `aria-busy`; chatbot streaming + workflow execution status need `aria-live`.
**H. Data tables (1.3.1)** — `components/data-table/DataTable.tsx` → `mantine-datatable`: `<th>` headers, `aria-sort`, caption/`aria-label`, announced empty/loading/error. The library renders a sortable header as `<th role="button">` and emits no `aria-sort` (#832) — read `node_modules/mantine-datatable` rather than assuming.
**I. Motion / timing (2.2.x, 2.3.x)** — `prefers-reduced-motion` overrides for animations in `widgets.css`, shell CSS, page styles; `autoClose` < ~5s is a finding; no >3 Hz flashing.
**J. Plugin UI** — no plugin has a `spa/` folder; pages are `PageTemplates/*.template` (Auditor) or JSX strings in the plugin class (HelloPlugin). Sample those with A/C/E/F; `plugin-creator` skill should state a11y expectations (drift finding if not).
**K. Tooling** — as of 2026-11-16: `npm run lint` reports 98 warnings against `--max-warnings=98`, of which 38 are jsx-a11y (15 `no-autofocus`, 23 mouse-only handlers); the budget mixes all rules. The linter has no `jsx-a11y` component map, so it cannot see Mantine components, and `control-has-associated-label` is off. An axe smoke test exists (`tests/AutoNate.E2E.Tests/AxeAccessibilitySmokeTests.cs`, slim tier): 4 routes, initial state, `wcag2a`/`wcag2aa`, fails on critical or serious. Gaps tracked in #844.
**L. Run axe yourself** — the lint and the 4-route test miss most of the UI, so scan. `axe-core` is already in `src/AutoNate.Spa/node_modules` (a dependency of the lint plugin). Start the app on a scratch database the way `AutoNateE2EFixture` does (`ConnectionStrings__Default`, `Bootstrap__Admin*`, `AUTONATE_ALLOW_RUNNING_WITHOUT_DAPR=true`), sign in through the form, then for each route `page.addScriptTag({ path: '.../axe-core/axe.min.js' })` and `axe.run` with the WCAG tags. Seed a record type WITH custom fields, or the record form's unlabelled fields (#831) will not be scanned. Mantine inputs have no `type` attribute, so select the login fields by label. The 2026-11-16 scan covered 25 routes: 13 failing contrast pairs on 9 routes, one unnamed close button.

Mantine facts that decide findings (verified against 9.5): `Tooltip` describes, never names; `Input.Wrapper` without a shared `id` does not label a nested input; `withAsterisk` is visual, only `required` is announced; `Alert` defaults to `role="alert"`; `Menu trigger="hover"` does not open on Enter (#830); filled variants are white-on-shade-6 unless a `variantColorResolver` says otherwise (#833).

Severity: High = blocks an AT user on a primary task or any default-theme contrast failure. Medium = degraded with workaround. Low = defense-in-depth. Remediation for custom-widget findings usually routes to the `mantine-custom-components` / `mantine-combobox` skills.
