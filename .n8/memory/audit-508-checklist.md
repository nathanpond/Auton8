# Section 508 / WCAG 2.0 AA audit checklist (AutoNate-specific)

Harvested from `.claude/skills/audit-508` on 2026-08-30. Scope: `src/AutoNate.Spa/src/`, plugin SPA under `plugins/<name>/spa/`, shared chrome. Mantine v9 supplies the baseline (focus trap, Escape, ARIA on Modal/Menu/Combobox); the audit hunts where AutoNate code *escapes* it. Baseline target: WCAG 2.0 AA (508 floor); call out cheap 2.1/2.2 wins.

**A. Text alternatives (1.1.1)** — `<img alt>` (decorative `alt=""`); FA glyphs `<i className="fa fa-…">` need an accessible name on the parent `Button`/`ActionIcon` (`aria-label`, visible text, `title`); standalone `<i onClick>` is always wrong; known FA users `SiteBrand.tsx`, `IconPicker.tsx`. Detect: `grep -rn '<i className="fa' src/AutoNate.Spa/src/` then inspect the parent.
**B. Contrast / color-only (1.4.1, 1.4.3, 1.4.11)** — 4.5:1 text, 3:1 large text + focus rings. `SiteAppearance` is admin-configurable: `applySiteAppearanceToDocument` in `src/AutoNate.Spa/src/lib/siteAppearance.ts` writes `--mantine-*`/`--app-*`; check the configurator validates contrast, that scheme inference from `surfaceBg` luminance doesn't flip wrongly near mid-luminance, that header/sidebar fg/bg pairings have a floor. Status pills / `.row-archived` / `.notification-unread` in `widgets.css` must not be color-only. Compute ratios; cite them.
**C. Keyboard (2.1.1, 2.1.2, 2.4.3, 2.4.7)** — Tab reachability, no traps outside modals, no `outline: none` without replacement, only `tabIndex` 0/-1, skip-to-content in `AppShell.tsx`, custom widgets in `src/AutoNate.Spa/src/widgets/` handle Enter/Space/arrows/Escape, `AgentSidebar` (position: fixed) opens/closes/focuses/returns focus by keyboard. Detect: `grep -rn onClick src/AutoNate.Spa/src/ | grep -E '<(div|span|li|td) '`.
**D. Focus management (2.4.3, 2.4.11)** — non-Mantine dialogs are findings (`components/ConfirmModal.tsx` is canonical); route change moves focus to `<h1>`/main (check `router.tsx`, `ProtectedRoute.tsx`); toasts never steal focus.
**E. Forms (1.3.1, 3.3.x, 4.1.2)** — Mantine `label` prop wires `htmlFor`; errors via the `error` prop (wires `aria-describedby`/`aria-invalid`), not a stray `<Text c="red">`; `required`/`aria-required`; fieldset/legend for groups; login form is highest priority (pre-auth, most trafficked).
**F. Structure / landmarks (1.3.1, 2.4.x)** — one `<h1>`, no skipped levels, per-route `<title>` (index.html ships `AutoNate`), `<html lang>`, banner/nav/main/aside landmarks from `AppShell`, real lists.
**G. Live regions (4.1.3)** — Mantine `notifications` uses role=status; spinners paired with `<VisuallyHidden>Loading…</VisuallyHidden>` or `aria-busy`; chatbot streaming + workflow execution status need `aria-live`.
**H. Data tables (1.3.1)** — `components/data-table/DataTable.tsx` → `mantine-datatable`: `<th>` headers, `aria-sort`, caption/`aria-label`, announced empty/loading/error.
**I. Motion / timing (2.2.x, 2.3.x)** — `prefers-reduced-motion` overrides for animations in `widgets.css`, shell CSS, page styles; `autoClose` < ~5s is a finding; no >3 Hz flashing.
**J. Plugin UI** — sample 2–3 files under `plugins/<name>/spa/` with A/C/E/F; `plugin-creator` skill should state a11y expectations (drift finding if not).
**K. Tooling** — `eslint-plugin-jsx-a11y` IS installed (^6.10.2; ~95 open jsx-a11y warnings under the SPA lint cap as of 2026-08-30); `axe-core` / `@axe-core/react` are NOT. Recommend burning down the jsx-a11y warnings, adding axe, plus a Playwright + `@axe-core/playwright` golden-path CI check; document the baseline in CLAUDE.md/README.

Severity: High = blocks an AT user on a primary task or any default-theme contrast failure. Medium = degraded with workaround. Low = defense-in-depth. Remediation for custom-widget findings usually routes to the `mantine-custom-components` / `mantine-combobox` skills.
